# 維護 ask-bridge 組織副本

目標是保存必要修正，同時持續接收原作者更新。讓使用者透過功能結果決定是否採用新版；Git 整合、差異比較與保存由代理人處理。第一次提術語時用一句白話解釋用途。

先讀 [references/maintenance-state.md](references/maintenance-state.md)，了解實際來源、分支、修正與已知限制。進行官方更新或版本切換時，再讀 [references/update-workflow.md](references/update-workflow.md)。參考檔是交接紀錄，實際狀態仍須查 Git、命令路徑和執行檔資訊。

## 先界定本次工作

- 「檢查更新／解釋」：讀取與比較，提出具體結果。
- 「保存／上傳」：整理提交，推送到已確認的組織儲存庫；只推送本次需要的分支。
- 「整合官方更新」：建立候選版本，處理衝突，檢查功能與驗證證據。
- 「切換／回復」：依已確認的部署目標切換執行檔和操作 skill，更新本機部署紀錄。
- 「升版本／發布」：另讀專案 bump-and-release skill，先確認此組織副本的發布目的地與套件名稱。

使用者既有授權持續有效；不要因例行 Git 操作再次詢問。只有缺少目標、可見性、驗證範圍、部署選擇等會改變結果的資訊時才詢問。要求先規劃時不實作。此 skill 不授予每次檢查都自動部署、發布、向原作者發送 PR 或對外聯絡的權限。

## 保存與來源

1. 檢查 `git status`、目前分支、staged 差異、remote 與本機命令指向。保留使用者既有修改，包含先前 npm 安裝產生的 package 變更。
2. `origin` 應指向組織儲存庫，`upstream` 應指向 `doggy8088/ask-bridge`。這些是遠端連線名稱；來源不符時先判斷既有工作，避免直接取代不明遠端。
3. `main` 保存官方來源；`codex/local-fixes` 保存組織修正。候選分支用 `codex/` 前綴。既有等價分支可繼續使用，不為命名而重寫歷史。
4. 依功能拆成合理且可理解的提交，保留上游作者、授權與來源。依 AGENTS.md 使用 Conventional Commits 首碼與繁體中文說明。
5. GitHub Fork 只複製遠端來源；尚未提交的本機修改需要 commit 和 push 才會存進組織儲存庫。私有獨立副本仍能使用 upstream 整合，但不具 GitHub Fork 關係。
6. 推送前檢查本次 staged 清單。瀏覽器 HTML、截圖、cookie、登入設定、對話原文、測試輸出及編譯產物保留在忽略的本機位置。推送後讀回遠端分支 SHA，確認與本機相同；不要只看命令印出成功。

## 整合官方更新

- 取得 upstream，記錄基底與候選的 commit SHA（Git 用來識別版本的代碼），查看差異和發布說明。
- 在候選分支或獨立 checkout 整合。需要隔離 checkout 時，優先使用可用的受管理 worktree 工具，先查可重用的工作目錄。
- 個人修正逐項記為「保留、官方已取代、需要調整」。以行為和案例判斷，避免只按檔名或行號決定。
- 共享的 `codex/local-fixes` 優先 merge，保留歷史；rebase 只用於適合重排的私人候選工作。不要對共享分支 force push。
- 沒有文字衝突不代表相容。尤其檢查回覆與對話綁定、完成判斷、逾時擷取、狀態碼，以及輸出檔與圖片流程。
- 官方已提供等價修正時，移除對應個人實作並保留比較證據，讓長期差異縮小。不要為了保留舊修正而維護重複流程。

## 執行檔與操作 skill

- 平常的命令應連到專案工作目錄之外的已保存執行檔；候選建置使用獨立 target 目錄。候選建置不得直接覆寫使用中的執行檔。
- 建立 Fork 不會更改更新器。使用自訂修正版時，`ask-bridge update`、官方安裝器、`make install` 和重新安裝官方 skill，都要先核對實際來源及影響。
- 切換前保存目前執行檔、SHA-256、來源 commit、驗證狀態與操作 skill，並保留上一份可回復版本。新命令路徑切換後，用實際路徑和版本輸出確認。
- `skills/ask-bridge/SKILL.md` 是組織保存的操作指引；專案外的全域副本是安裝結果。同步時先比較全域修改並保存差異，不得直接覆蓋其他 session 的新內容。
- 同版本號不代表同執行檔；用 commit 與 SHA-256 辨識本機修正版。未驗證的候選不得僅因編譯成功就稱為穩定版。

## 驗證與回報

原始碼修改後依 AGENTS.md 執行 `cargo fmt --all -- --check`。功能驗證依使用者本次授權及工作範圍進行；只保存或寫文件時不冒稱重新跑過測試。過往測試結果須標明日期和限制。

回報以下具體結果：

- 組織儲存庫、分支及已推送 commit。
- 保留、移除和調整的修正。
- 本次執行的檢查、未驗證功能及已知失敗。
- 使用中的執行檔／操作 skill 是否已切換，以及回復位置。

同步更新維護狀態。若遇到已知失敗，保存和上傳仍可完成；部署前須明確評估影響，不把未完成問題寫成已解決。
